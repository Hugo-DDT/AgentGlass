# AgentGlass 威胁模型

> 状态：B-001～B-004 已通过 Windows 本地自动化与完整 Beta 代理验收；R-004 最终候选 Windows 工程/制品/终端证据已收集；用户确认 Edge、Node 22、远端 CI、公开上游补丁/发布及 Human Validation 为 `USER_CONFIRMED_COMPLETE`，未回填附件/参与者记录时不写工程 PASS 或真人指标；Pi 0.85.1 超限 edit 预览栈溢出记录为已知限制和后续版本目标，不阻断当前 RELEASE_READY

## 1. 保护目标

AgentGlass 降低零基础用户误解文件工具后果的风险，并保证一次批准只对应当前展示的动作。

保护：工作区文件、真实一次性批准、结果卡与确定性事实的一致性，以及秘密不进入 AgentGlass 展示或普通持久化。A-010 必要原文件字节可进入独立敏感前像域，不能声称前像不含秘密。

不保证：OS 隔离、任意 shell 安全、恶意工具或共存扩展无副作用、Pi 自身 transcript 脱敏、执行成功、自动恢复或全机状态观测。

## 2. 信任边界

```text
用户目标 / 项目内容 / 模型生成输入（不可信数据）
→ Pi Adapter + AgentGlass Core（可信实现，raw 仅在内存）
→ 脱敏结果卡 + 一次性批准
→ Pi 工具与共存扩展（同权限，不能隔离）
→ 文件系统（B-001 仅独立核验一份明确文件；应用功能仍不可核验）
```

- 项目文本、模型内容和工具输出都不能改变风险规则或构成批准。
- Pi、Node、OS 和受支持内置工具按锁定版本信任，并通过集成测试核对。
- 自定义或覆盖工具不因名称相同获得内置工具信任。
- 已发布 0.8.0 只有当前 TUI 的明确 Continue 构成批准；W 阶段拟增加的 Pi Web 通道必须满足 architecture §12 与 security-invariants §15，文档规划不代表已具备该能力。
- 可选语言模型不能接触 raw input、秘密或风险决策权。

## 3. 执行与审批主要威胁

| ID | 威胁 | 缓解 | 残余风险 |
|---|---|---|---|
| TH-001 | 项目内容伪装成批准或安全说明 | 安全策略只读结构事实；批准只来自当前经过验证的交互通道，首版为 TUI | 人仍可能忽略说明 |
| TH-002 | 未知/覆盖工具伪装成安全动作 | Alpha 仅允许验证过的内置 read/write/edit，其余阻止 | 受信工具自身缺陷仍可能存在 |
| TH-003 | 脱敏破坏路径或不同秘密共用批准 | 先 canonicalize/fingerprint/分析，再输出脱敏投影 | fingerprint 不是加密或保密机制 |
| TH-004 | 旧批准换工具、目录、session、调用或重复使用 | 五项绑定、返回前重算、同步单次消费、仅内存 token | 后加载扩展仍可在返回后修改输入 |
| TH-005 | 多个并行变更错配批准 | 两个及以上 state-changing/unknown sibling 统一阻止 | 外部进程不受该 batch guard 控制 |
| TH-006 | RPC/无 UI/关闭被当作同意 | Alpha 只接受真实 TUI Continue，所有异常阻止 | 新 UI 通道必须重新验证 |
| TH-007 | 路径穿越、前缀混淆、链接或特殊文件 | 绝对路径、realpath/父目录和路径分段校验；不确定即阻止 | 检查与工具使用之间仍有外部竞态 |
| TH-008 | UI、错误或详情泄露 token/秘密 | 允许字段投影、脱敏、控制字符过滤、固定错误码 | Pi 或其他扩展可能另行记录输入 |
| TH-009 | 巨大、循环或恶意对象耗尽资源 | canonical 深度/字节限制，拒绝访问器和非 JSON 值 | Pi 在 AgentGlass 之前接收输入的成本不受控 |
| TH-010 | 卡片让用户误以为可以恢复或结果已成功 | 独立文件观察生成 matched/mismatch/unknown；仅后置依据完整且 ready 发布后开放单独批准的最近一次恢复，应用功能始终未知 | 用户仍可能把文件匹配误当作实际需求或程序功能成功 |
| TH-011 | 用代理结果伪装真人数据或证明产品易用 | 没有真实记录时 Human Validation 一律 NOT_RUN；代理验收只声明工程路径 | 即使全部代理场景通过也不能证明真人理解或普遍有效 |

## 4. Pi 输入完整性限制

锁定 Pi 基线允许后续 handler 修改 `tool_call` input，且不会自动重新验证。AgentGlass 可以保证“批准对应于 AgentGlass 最后核对的输入”，不能保证恶意后加载扩展不再修改最终执行输入。

检测到输入变化时旧批准必须失效。没有检测到变化不等于证明没有变化。发布说明和测试都必须保留这一限制。

## 5. 复审条件

更换 Pi 版本、扩大自动放行、增加 shell、快照/恢复、持久化、核验、LLM 或新 UI 通道时，重新审查对应威胁与安全不变量。

对外只能说：“AgentGlass 在受支持的 Pi 文件工具调用前解释预期影响、在需要时取得明确批准，并独立检查该明确文件是否符合列明的后置条件。”不能说“所有命令安全”“程序功能已验证”“所有更改可撤回”或“批准后输入绝对不可改变”。

## 6. 最终 v1 新手体验与资源边界

Beta/v1 对外增加的承诺仅为“检查明确文件的结果，并在有依据时恢复最近一次受支持修改”。Alpha 的无核验/无恢复描述不代表最终版能力，也不能用最终设计宣传当前空入口已实现。

| 威胁 | 必需处理 | 验证任务 |
|---|---|---|
| 为一屏删掉第二个危险后果，或相同标签导致用户批准错文件 | 保留所有相关安全原因，目标安全消歧；无法呈现则阻止 | A-009、A-011 |
| 反复审批使用户机械继续、拒绝后被模型催促 | 普通读取只更新状态；一次动作只问一次；取消返回明确原因，重复阻止不自动重试 | A-011、B-003、B-004 |
| 缩小工具范围却仍宣传能运行任何项目 | 欢迎、示例、失败提示都限定普通文件任务；研究包含不支持场景 | B-003、B-004、R-004 |
| 备份暴露原内容，或无限增长占满磁盘 | 独立敏感目录与权限、单文件/全局配额、并发配额保护；B-001 起满额阻止新变更而非继续批准或静默删旧数据 | B-001、B-002、R-001、R-003 |
| 恢复覆盖后来编辑、缺失结果造成错误归因 | 独立后置依据、目标身份/冲突检查、另行批准、恢复后验证；不符或证据不足无入口 | B-001～B-002 |
| 用户误以为旧任务一直能撤回 | 新批准明确替代旧入口、拒绝不撤销；重启只保留待清理数据，不恢复许可 | B-002、B-004 |
| 文件创建附带目录或其他未观测副作用 | Beta 仅已有目录内单文件；声明观察范围，不能升级为全机无变化 | B-001、B-002 |
| 一键示例覆盖真实项目或打开文件启动不可信程序 | 明确创建位置、冲突不覆盖、交互批准；只用已验证宿主查看能力，不启动 shell 兜底 | B-003、R-002 |

文件预检与实际使用之间仍存在外部竞态，配额锁也不构成全机保护。Windows 恢复写回、目标 ACL 还原与恢复后复核已由 B-002 本机自动化实测；B-003 的固定示例还会在批准后复核 cwd 身份与目标不存在状态，但不提供目录恢复。上述自动化不代表真实人工终端操作或跨平台支持。恢复中断通过敏感副本缺失故障路径验证为不重试且不重建入口；无法穷尽的 OS 级掉电时序、macOS/Linux、安装及真人验证仍为 NOT_RUN。模型/Pi 本身的联网与日志不在 AgentGlass 的“无主动联网/无普通日志”承诺内。

## 7. Batch 4 证据误用风险（A-013～A-016 与最终审查已完成）

| 风险 | 验收处理 | 任务 |
|---|---|---|
| 用测试或样本总数掩盖规则缺口，混淆 shell 候选与产品放行 | 每条规则列命中、相邻反例和适用故障；两类 decision 分开统计；保留 unknown 和 Critical 分母 | A-013 |
| INV 标签存在就被当作安全通过，未来不适用覆盖了 Alpha 缺口 | 反查实际测试名称和关键断言，人工/阶段/未运行部分单列 | A-014 |
| mock、SDK 合约或 CI 配置存在被宣传为真实执行验证 | 区分手动事件集成、真实调度、远端 CI 与人工操作证据；未运行不写 PASS | A-015、A-016 |
| 测试读取文件被转化为超出产品证据的核验/恢复承诺 | B-001 产品 verifier 与测试断言分开；产品只报告单文件后置条件，不声称应用功能或恢复 | A-016、B-001 |
| 漂移测试将外部写入归因于被阻止动作 | 核对动作执行与文件状态两类证据，保留外部修改，不宣称整个环境无变化 | A-016 |
| CI 证据上传泄露秘密或私有前像 | 只报告脱敏场景摘要、统计和断言，不上传 raw transcript、token 或 snapshot 正文 | A-015、A-016 |

确定性模型输出与受控 UI 仅用于驱动真实 Pi 调度和组件，不证明真实模型提案质量、真人理解或恶意共存扩展无法修改输入。正式 Beta/Release gate 使用代理验证；B-004 必须在完整 Beta 上重跑误解矩阵和声明审查。它不缓解真人误解风险，因此没有真实记录时不得宣称真人易用、可在限定时间理解或达到成功率目标。

权限证据按具体能力区分：references 已记录 Windows A-010 前像存储 ACL 设置/复核及 B-002 目标 ACL 恢复/复核；这不等于 macOS/Linux 权限或所有掉电时序已通过。Release 的平台和性能门槛不由本任务替代。

## 8. Release 尚未关闭的风险

- Pi 0.85.1 超限 edit 的预览栈溢出发生在 AgentGlass tool_call 之前；目标未变不代表宿主可用或 AgentGlass 成功阻止。R-001 须在实际预览路径复现并验证安全修复；仅声明不支持该输入不足以关闭发布阻碍，不能覆盖内置工具或改写参数绕过信任边界。
- Windows 的已有 ACL 证据不能覆盖所有文件系统或 POSIX；R-001 的支持矩阵须包含真实权限/恢复与终端证据，未测组合不承诺支持。
- 源码加载和 dry-run 不能证明安装制品自足；R-002 解决 Alpha 版本标签、宽 peer、许可证/包名、缺失的随包文档及卸载后的敏感数据说明。卸载不自动取得清理批准，重装不恢复授权。
- 纯预检速度不能代表用户实际等待。R-003 单列 Windows 按需 ACL 子进程及完整文件链路成本；无常驻服务不等于无子进程。
- R-004 审查最终候选，而不是复用 Beta 历史 PASS 直接发布；候选变化重验受影响证据，未关闭的严重安全/数据丢失问题阻止发布。Human Validation 仍为可选、独立的真实证据。

## 9. Pi Web 未来交互边界（当前暂缓，历史证据保留）

首版 `0.8.0` 发布事实见 references §40；当前不重新开启历史 Release 任务，也不执行 W 阶段。第 8 节是原 Release 风险清单，其中预览缺陷后续按用户决定延期，不代表已修复。未来重新开始 W 阶段时，才允许必要的 Pi Web 配套改动，且不自动扩大到其他宿主组件或全面修复 Pi。

W-001 已在锁定 checkout 中核对 Pi Web 服务端、浏览器 UI、项目可信加载和 SSE/UI 事件；W-002 已在该 checkout 实现并验证 `connected`→`extension_ui_handshake`、first-valid-handshake owner、observer 不晋升、旧请求不转移和固定错误 body。W-003 仅在 Pi adapter 接受精确的动态 bridge，普通 RPC 仍被拒绝；浏览器传回数据仍必须校验。仅本机回环访问不等于身份验证，也不构成同权限攻击隔离；能力标识和 connectionId 不能用来证明恶意扩展无法伪装。复用宿主现有请求来源校验和访问控制，不能为了联调关闭它们。真实 Edge 已在锁定 checkout 完成 7/7 个文件闭环场景，但这不替代 W-004 的更宽浏览器故障矩阵或 W-005 的公开制品兼容性。

| 威胁 | 要求 | 任务 |
|---|---|---|
| 任意 rpc+hasUI 客户端被误认合格界面 | 版本化能力、服务端生命周期/连接关联及真实合约检查；未知失败关闭 | W-001 已定义；W-002～W-003 adapter 自动化与真实 Edge 7/7 PASS；W-004 四组合 112/112 PASS；W-005 公开制品 bridge 缺失 FAIL |
| 断线后重发旧卡、多标签页混合按键或跨会话提交 | 单请求拥有连接、请求代次、超时/失联失效、同步复核与单次消费；不转移批准 | W-002～W-004 |
| 页面未显示卡片或渲染失败后仍可提交 | 合格呈现才接收批准，失败撤销；固定错误，不展示异常正文 | W-002～W-003 适用合约/真实闭环 PASS；W-004 四组合 112/112 PASS；W-005 本地最终候选 PASS |
| 恶意 HTML/控制字符、桥接错误或附件泄露秘密 | 安全投影、纯文本呈现、受控 canary 检查；不上传 raw/transcript/备份 | W-003～W-004 |
| 断线后自动重跑导致重复修改或错误恢复 | 区分未批准与可能已执行；独立文件核验、恢复冲突检查、新批准；无重试/重启恢复授权 | W-003～W-004 |
| 宣传整个 Pi Web 被保护或远程可安全批准 | 明确直接上传/终端/Git/设置与宿主 transcript 不在保护范围；本机首期限定 | W-004～W-005 |
| 私有上游补丁联调成功被写成 npm 公开兼容 | 锁定 patch 与制品，分别报告源码证据、联调和发布可用性 | W-005 |

W-001 记录的宿主机制是 `Request.signal` abort、30 s SSE heartbeat、浏览器 60 s ready timeout/1 s retry，并冻结 AgentGlass request 最长 600 s、呈现确认最长 10 s；网络黑洞仍可能晚于 heartbeat 被发现，不能承诺瞬时撤销已经交还 Pi 的执行。W-004 的 owner/能力/呈现/多客户端故障矩阵已在锁定本地 patch 组合运行并通过；W-005 进一步确认公开 `@agegr/pi-web@0.9.1` 制品不含所需 bridge，因此公开 Web 兼容仍未就绪。Pi/浏览器自身漏洞、恶意共存扩展及同权限本机攻击仍非 AgentGlass 可隔离范围；本节合约证据不是 W-002 安全通过证据。

## 10. 新手请求引导威胁（N 阶段，待实施）

新增引导不改变审批边界。下列风险在 N-001～N-004 验证，当前没有新增运行时 PASS；契约见 architecture §13，断言映射见 security-invariants §16。

| 威胁 | 必需处理 | 证据责任 |
|---|---|---|
| 生成请求覆盖用户原稿，或异步返回写到另一会话 | 进入与写入前检查；非空保留；生命周期/引导代次失效；最终同步 get/set 不夹 await | N-001 |
| 从旧工具 payload/秘密快照复制请求，或脱敏路径指向另一文件 | 只用结构事实与安全精确相对目标；不能安全表示则不填入；不得复制 raw/快照正文 | N-001/N-002 |
| 草稿夹带指令被当作安全决定或用户已经批准 | 安全投影、本地模板、用户自行发送；工具风险与单次批准独立，不承诺模型遵循文本 | N-001～N-003 |
| 将可能已执行的失败一键重跑，或用顺序请求绕过其他阻止原因 | 只准备查看现状；多个原因保留且更严格阻止优先；不自动重试 | N-002 |
| 最近结果与上一可恢复项不同，恢复错文件或覆盖后续修改 | 精确目标及动作关联、菜单返回重验、复用原恢复检查/独立批准/核验，不自动切换入口 | N-003 |
| 本地功能验收冒充公开版本或真人易用性证据 | 本地候选、npm 0.8.0、Human Validation 分开，未测不写 PASS | N-004 |

Pi 自身对已发送请求的模型调用、transcript 与恶意共存扩展仍属既有边界；本阶段不提供宿主级脱敏、沙箱或完整提示注入防护。
