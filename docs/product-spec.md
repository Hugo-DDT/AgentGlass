# AgentGlass 产品规格

> 版本：1.8 · 2026-09-14 · 状态：完整 Beta 代理验收已通过；真实 Pi/PTY 已覆盖支持、恢复、阻止、mismatch、unknown 与敏感 snapshot 边界；Release 候选已按 R-001～R-004 验收；加载增量预算经用户确认调整为 P95 ≤350 ms；用户确认 Edge、Node 22、远端 CI、公开上游补丁/发布及 Human Validation 为 `USER_CONFIRMED_COMPLETE`，未回填附件/参与者记录时不写工程 PASS 或真人指标 · 唯一宿主：Pi

## 1. 产品只解决一件事

AgentGlass 帮助非技术用户在 Pi 中完成普通文件任务：改变前看懂结果，改变后知道哪些已确认，需要时恢复这一次受支持的修改。Alpha 先完成执行前审批，Beta 补齐文件核验与恢复，v1 发布完整闭环。

用户批准的是**预期结果和影响**，不是命令、工具参数或隐藏推理。AgentGlass 不承诺操作安全、一定成功或一定能恢复。

当前 Beta 已具备核验、受限恢复与欢迎示例；第 2～3 节是 Alpha 历史范围，当前交付以第 5～6 节为准。Release 不扩展文件工具范围，也不以包版本仍带 Alpha 标签否认已有 Beta 能力。

## 2. Alpha 用户体验

用户只需会打开已配置好的 Pi，并用自然语言描述目标。安装 Pi、配置模型和完整的新手安装器不属于 Alpha。

Alpha 默认界面只回答四个问题：

1. 继续后会发生什么？
2. 最需要注意什么？
3. 当前能否自动恢复？
4. 继续还是停止？

命令、参数、指纹和风险代码不进入主界面。技术详情可以展开，但危险原因不能被折叠隐藏。

## 3. Alpha 范围

Alpha 只支持已验证的 Pi 内置文件工具：

| 动作 | Alpha 行为 |
|---|---|
| 读取普通项目文件 | 确定为项目内、非敏感、只读后自动继续，并显示一行提示 |
| 新建普通项目文件 | 展示结果卡，明确批准后继续 |
| 修改普通项目文件 | 展示将被替换的目标和不可自动恢复说明，明确批准后继续 |
| shell、Git、安装、联网、进程、自定义工具 | 当前版本不支持可靠解释，阻止并给出下一步建议 |
| 敏感文件、项目外路径、链接或范围未知 | 阻止；不要求零基础用户承担未知判断 |
| 同一批次两个及以上变更或未知动作 | 阻止并要求 Pi 一次只提出一个变更 |

Alpha 包含：确定性分类、脱敏前指纹、简明结果卡、单次精确审批、受支持普通 `write/edit` 的有界敏感 pre-image evidence、失败关闭和必要自动化测试。pre-image 成功或失败均固定 `canRestoreNow=false`、恢复等级 `unknown`。

Alpha 不包含：restore、持久化事件日志、执行后核验、学习档案、时间线、遥测、Web UI、LLM 风险判断或多宿主框架。A-006 的有限纯函数 Bash classifier 不扩大执行支持面。

## 4. 成功标准

自动化要求：

- 未知、敏感、越界和不支持动作没有任何自动放行路径。
- 批准与 fingerprint、toolName、cwd、sessionId、toolCallId 精确绑定且只能使用一次。
- 原始工具输入和秘密不进入 AgentGlass UI、普通日志或持久化。
- 无 UI、输入变化、规则错误或必要预检失败时阻止动作。
- 每条规则至少有一个命中用例、一个相邻反例和适用的故障用例；不以固定 fixture 数量冒充质量。

产品要求：

- 用户无需查看命令即可说出将改变什么。
- 用户能区分“不能自动恢复”和“操作失败”。
- 结果卡默认一屏可读，Continue 不作为默认焦点。

“适合零基础用户”必须由真实用户测试支持。没有实际记录时一律写 `NOT_RUN`，不能用模型模拟或模板测试替代。

## 5. 最终 v1 的产品范围

首发定位为“Pi 中的新手文件助手”。代表任务为创建一份活动说明、修改文案、整理一个文本文件中的内容。可以生成代码文件，但不保证程序功能正确。安装依赖、运行项目、部署网站、批量删除和后台程序管理不属于首发承诺；不能以“帮你把任何项目跑起来”作为演示或宣传。

| 用户需要 | v1 必须提供 | 最小实现 |
|---|---|---|
| 知道从哪里开始 | 一个入口、一份随包示例、一条可直接使用的自然语言目标 | Pi TUI 内的 `/agentglass` 欢迎/帮助入口，不增加独立应用 |
| 知道当前作用范围 | 始终能找到当前工作文件夹的脱敏名称与支持范围 | 启动时显示一次；切换目录后更新 |
| 看懂将改变什么 | 具体文件标签、新建/替换/局部编辑区别、相关后果 | 本地模板；技术详情按需查看 |
| 减少打断 | 普通读取不弹窗；每个需要批准的动作只问一次 | 连续读取更新一条状态，不合并或复用变更批准 |
| 看懂执行结果 | 同一动作卡更新为已确认、不符或无法确认 | 只观察该文件，不扫描整个项目 |
| 改错了能处理 | 受支持单文件恢复、冲突时保留当前文件 | 当前会话最近一次仍有恢复依据的变更；新建文件的恢复是删除该文件，必须另行批准 |
| 卡住后知道怎么办 | 原因和一个可行下一步 | 顺序重试建议交给 Pi；完全不支持的目标明确结束，不要求用户改命令 |

Beta 必须交付受支持文件核验与恢复，不能只从两者中任选一个就发布 v1。B-001 已交付单文件核验，B-002 已交付当前会话最近一次恢复及有界清理，B-003 已交付同一入口的欢迎/示例路径；仅当后置基线、身份、字节和权限完整时才显示恢复入口。B-004 已在当前实现上完成代理验收；这不等于 Release 或真人验证完成。

v1 不实现：通用 Bash 解析、学习档案、个人熟悉度模型、课程、独立时间线、Web Dashboard、常驻进程、额外 LLM 调用、遥测、账号或通用宿主框架。少量 shell 场景只能在后续独立立项，通过真实需求与环境/副作用验证后加入；不得为了跑通演示关闭保护。

## 6. 零基础上手路径

1. 安装前明确：需要已配置模型的 Pi；AgentGlass 不提供模型账号，也不能替 Pi 消除终端入口。分别验证“Pi 已就绪后上手”和“从空白电脑安装”，不能把前者冒充后者。
2. 安装完成第一次打开 Pi 时，在 TUI 提示 AgentGlass 已启用、脱敏当前文件夹和支持的文件任务。无需选择风险等级、配置规则或填写密钥；之后只在主动打开帮助或目录变化时展示。
3. 用户从 `/agentglass` 选择“试一个例子”。创建示例文件夹先说明位置并取得明确同意，不覆盖已有目录；这仅限 B-003 的固定无秘密示例准备，不开放普通 write 的隐式目录创建，须有独立预检与精确单次审批，失败保留并说明实际已创建内容，不自动删目录或承诺恢复示例目录；通过受支持宿主方式进入后才能开始，没有可靠切换能力时给出具体操作说明。
4. 示例预置“帮我修改这份活动说明”的目标，用户可复制到 Pi。示例准备先取得单独同意；准备完成后的练习有两次决定：接受这次内容变化、可选恢复；不要求理解 Git、diff、shell 或权限配置。
5. 任务结束更新原卡并显示核验范围；恢复入口出现在该结果旁。普通文件可通过已验证的宿主能力查看；否则说明请在 Pi 对话中请求查看，不为了提供打开按钮启动 shell。B-003 已在锁定 Pi 0.85.1 上提供同一 `/agentglass` 的欢迎、帮助、最近结果、恢复/清理说明和固定示例；B-004 的真实 Pi/PTY 已覆盖主要支持/恢复/阻止、mismatch、unknown 与敏感 snapshot 边界。

未知操作的拦截提示不可建议关闭 AgentGlass 或绕过保护。新手不承担判断陌生命令是否安全的责任；如果实际需求主要是运行项目，应重新评估产品定位，而不是将安装/运行失败记成文件助手成功。

## 7. 轻量化验收预算

以下是发布验收目标。B-004 已有代理场景、制品大小及配额边界的局部证据（references §26），不等于正式性能与安装验收。R-001 验证终端/平台，R-002 验证安装与配置成本，R-003 测量性能/资源，R-004 对最终候选复验；未测项保持 NOT_RUN。

- 使用一个 Pi 扩展包；额外常驻进程、监听端口、服务端、数据库服务和 AgentGlass 主动网络请求均为 0。Pi 自身模型联网另计且明确告知。Windows 当前通过按需短时 PowerShell 子进程设置/核对 ACL；它不是常驻服务，必须报告耗时，不能声称零子进程。
- 新手新增必填配置、额外密钥和风险模式选择均为 0；设置仅在 `/agentglass` 中提供帮助和受支持的本地恢复数据清理，不建设置系统。
- 标准 80×24 终端上的普通单文件审批卡一屏可读；安全原因不能为满足一屏而丢失。一次变更只产生一次审批，不附加“你确定吗”；恢复是独立变更。
- 复用现有 Pi UI 和 Node 标准库；新增运行时依赖须证明现有能力不能满足任务。制品增量目标 ≤2 MiB，按实际安装制品的解包字节判定，同时报告压缩字节；不含宿主、开发依赖与用户恢复数据；超标要分析原因后调整设计。
- 同机相对裸 Pi 的扩展加载增量目标 ≤350 ms；普通输入 ≤64 KiB 时纯预检 P95 ≤50 ms。文件 I/O、快照、用户等待和模型耗时分开报告；安全检查不得因性能指标被跳过。350 ms 门槛由用户在 2026-09-14 的发布确认中明确调整，后续仍须如实报告完整分布，不得删除离群值。
- 仅保存当前任务关联和有界恢复数据，资源规则以[架构](architecture.md)为准。禁止完整 transcript、全目录快照、后台索引和自动扫描整个电脑。
- 正式代理验收对完整产品逐项覆盖目标识别、停止/详情/继续、恢复限制、核验边界、未知、多变更和不支持任务；每项均须有适用的成功、拒绝/相邻反例及故障证据，并由真实 Pi 调度和独立文件断言证明可观察路径。代理验证不能证明用户理解、可读时间或易用性；没有真实参与记录时这些真人指标保持 `NOT_RUN`，不得宣传为已验证。

## 8. 永久边界

- v1 只支持 Pi。
- 不使用 LLM 决定或降低风险。
- 不声称 OS sandbox、完整 shell containment、万能 Undo 或防恶意共存扩展。
- 不展示或保存隐藏 chain-of-thought。
- 不建立账户、远程审批、数据库或遥测服务。

实现细节见[架构](architecture.md)、[风险模型](risk-model.md)、[结果卡](outcome-card-spec.md)与[安全不变量](security-invariants.md)。

## 9. Pi Web 未来阶段（当前暂缓，历史证据保留）

首版 `0.8.0` 已发布；第 2～8 节的首发/TUI 范围是当前交付基线。Pi Web 浏览器兼容属于未来阶段，现已按用户决定暂缓；仍不建设 AgentGlass Web Dashboard、远程审批服务或第二宿主。任务与验收以 development-plan §8 为准；此前 W-001～W-005 的本地联调、宿主候选和浏览器证据只作历史记录，不改变当前 `0.8.0` 的 TUI-only 公开声明。

交付必须包括浏览器中的读取、单文件修改前审批、核验、最近一次恢复，以及同一 /agentglass 的欢迎/帮助、示例和单独清理。优先复用已有卡片及键盘操作，不要求新增原生网页按钮系统；Stop 仍为默认。普通读取不弹审批，未知/不支持/敏感/越界动作仍阻止。

首期支持目标为 Windows 本机回环访问、Edge/Chrome、Node 22.19.0/24.14.0；Pi Web 0.9.1/Pi 0.85.1 已完成 W-001 锁定与合约证据，但仍不是已交付或公开兼容声明。Pi Web 配套改动允许进入独立任务，但未经可获得宿主制品验证不得宣称公开兼容。远程/LAN、手机及其他操作系统不在首期承诺内。

页面关闭、切换或断线不代表已经执行的变更被撤回。重新连接不能继续旧审批；有可靠现有会话证据才显示最近恢复入口，恢复依然单独批准。浏览器看不到完整危险信息时不能批准。

第 7 节预算继续适用 AgentGlass 增量；Pi Web 自己的服务、网络传输与资源单列，不算新增 AgentGlass 常驻服务，也不能从报告中省略。部署/模型前置条件仍须如实说明。Pi Web 上传、终端、Git、配置和其他直接操作不纳入 AgentGlass 保护，宿主原有会话/工具输出也不承诺全面脱敏。安装后界面不能让用户误以为整个 Pi Web 都受保护。

没有真实参与者记录时 Human Validation=NOT_RUN；完整兼容不是已证明新手理解率。此次文档修订不修改已发布 README、包版本或运行时代码，不构成新版本已交付。
