# AgentGlass Outcome Card 规范

> 状态：B-001～B-004 已实现并通过完整 Beta 代理验收；真实 Pi/PTY 已覆盖 mismatch、unknown 与敏感 snapshot 边界；用户确认 Edge、Node 22、远端 CI、公开上游补丁/发布及 Human Validation 为 `USER_CONFIRMED_COMPLETE`，未回填附件/参与者记录时不写工程 PASS 或真人指标；R-001=PASS_WITH_DEFERRED_EXTERNAL_DEFECT；R-004=RELEASE_READY=PASS（外部 Pi 预览缺陷为已知限制和后续版本目标） · 默认语言：zh-CN

## 1. 设计原则

结果卡必须让第一次使用 Agent 的人不用看命令，也能知道继续后会改变什么。

- 一张卡只解释一个动作。
- 普通动作默认一屏，一个主要结果；所有影响批准的危险原因和未知项均保留，可将同义项合并为一句，不能只保留最高风险而丢弃其他后果。
- 使用“预计”“会尝试”“无法确认”，不把预测写成保证。
- 不显示风险分数、reason code、指纹、session 或工具参数。
- High/Critical 后果始终可见；不能靠颜色或图标单独表达。
- Alpha 历史卡统一说明“当前不能自动恢复”。B-002 起，变更前只说明已保存副本并会在完成后检查；只有 `ready` 证据完整时才显示 `/agentglass` 恢复入口。

## 2. 默认布局

```text
下一步：<人类可理解的动作>

预计结果：<继续后最可能看到的一项变化>
需要注意：<最重要的后果或不确定性>
恢复：当前不能自动恢复这次修改。

[停止] [继续]
[查看详情]
```

`Continue` 不是默认焦点。初始焦点放在“停止”；Enter 只激活当前焦点。Esc、关闭、取消、超时和 UI 错误都等价于停止当前动作。

“查看详情”只展开已经脱敏的目标和证据说明，返回后仍未批准。不得让用户从卡片直接编辑工具输入。

详情第一层用普通中文回答“为什么需要这一步、哪份文件会变、哪些还不能确认”；用途没有可靠依据时直接说明未知。只有用户主动进入技术详情才显示经过脱敏的技术事实。按钮使用“停止这一步”“继续这次修改”等具体动作标签，正文和按钮不出现 Continue、TUI、sibling 等术语。

## 3. 各类动作

### 普通读取

读取满足全部自动放行条件时不弹审批卡，只显示一行：

```text
正在查看：活动说明.txt，不会修改它。
```

### 新建文件

```text
下一步：创建活动说明.txt

预计结果：当前工作文件夹中会出现活动说明.txt。
需要注意：AgentGlass 只能确认文件动作，不能保证内容能解决你的问题。
恢复：当前不能自动删除或恢复这次修改。

[停止] [继续]
[查看详情]
```

### 修改文件

```text
下一步：修改活动说明.txt

预计结果：活动说明.txt 中选定的内容会被替换。
需要注意：原内容可能丢失；请只在你接受这个结果时继续。
恢复：当前不能自动恢复修改前内容。

[停止] [继续]
[查看详情]
```

### 不支持或未知

未知影响不交给零基础用户批准：

```text
已停止：当前版本还不能可靠说明这一步会改变什么。
当前版本支持普通文件的查看和修改，暂不支持安装或启动程序。
你可以返回对话，选择一个文件任务。

[返回]
```

### 多个同时变更

```text
已停止：这次包含多个会改变内容或影响未知的操作。
请让 Pi 一次只提出一个变更。

[返回]
```

### 无审批界面

```text
已停止：这一步需要你的明确确认，但当前模式无法显示审批界面。
请回到有交互按钮的 Pi 窗口再试。
```

## 4. 文案与可访问性

- 先写结果，再写风险，不从技术名词开始。
- 每句只表达一件事；四行是普通场景的排版目标，不是截断上限。多个危险原因、未知范围或窄窗口时优先完整表达；无法安全呈现时阻止审批。
- 目标使用经过审查的可读标签；不显示秘密、原始 payload 或可重放 token。
- 用户字符串先投影脱敏，再过滤控制字符并限长；截断不得删掉危险原因。文件标签必须能区分实际目标，重名时显示安全相对目录；无法区分时不让用户盲目批准。
- 使用完整文字标签，不依赖 emoji、颜色、鼠标或动画。
- 窄窗口允许详情滚动，但主要结果、危险原因和按钮必须可达。
- “停止”只表示当前动作没有获得许可，不表示已经停止其他程序。

## 5. 验收

自动化覆盖普通读取、新建、修改、不支持工具、敏感/越界目标、多变更、无 UI、取消、输入变化、控制字符和长文本。

代理验收必须分别断言主卡在展开技术详情前呈现：将改变什么、哪里不确定、是否能够恢复；并验证详情、停止、Esc 和默认 Enter 不构成批准。该断言只证明界面内容与交互路径。没有真实参与记录时 Human Validation 保持 `NOT_RUN`。

## 6. v1 使用中的反馈

同一个动作只占用一张可更新的卡：待确认 → 执行中 → 已确认/不符/无法确认。Pi 的审批 modal 在 Continue 后关闭，因此 B-001 使用同一 actionId 与稳定 `agentglass-action` widget key 更新同一逻辑卡片，不重复打开审批，也不建立时间线。普通连续读取只更新 `agentglass-read` 一条状态。实际执行前不能显示“已执行”，任何工具返回成功都不能直接显示“目标已完成”。

B-002 核验阶段在 `ready` 发布成功后显示“可在 `/agentglass` 中恢复这一次修改”；不符、unknown、版本/证据/权限失败只说明当前不提供入口。新建文件使用“已记录修改前不存在”，不声称保存了不存在的内容副本。

Beta 修改前恢复文案：“已保存修改前副本；完成后会检查是否能恢复这一次修改。”备份失败则显示“未能保存修改前副本，这次修改已阻止”；不能继续展示 Alpha 的批准按钮。

B-001 执行后示例（仅限确有预期字节证据且独立读取匹配的场景）：

```text
已确认：活动说明.txt 与这次卡片列明的文件结果一致。
已知：工具报告完成；文件结论仍来自独立读取，不来自工具返回文本。
仍未知：这份文件是否满足你的实际需求，以及程序功能是否正确。
检查范围：仅独立读取这份明确文件，不扫描项目。
恢复：当前不能自动恢复这次修改。
下一步：你可以返回 Pi 继续后续文件任务。
```

“恢复这次修改”只有恢复依据完整、当前内容仍匹配执行后基线时显示。恢复确认卡明确写“将用修改前副本替换当前内容”，新建文件则写“将删除刚才创建的活动说明.txt”；首次焦点仍为停止。恢复后以独立检查结果更新原卡，不能只凭返回码写“已恢复”。

修改前存在上一次恢复入口时，卡片加一句“继续后，上一项将不再提供恢复入口”。未批准不撤销旧入口。旧会话/旧副本不做历史浏览，帮助入口仅提供清理及明确的数据说明。

## 7. 被阻止后的下一步

- 无 UI：“这一步没有执行。请回到有交互按钮的 Pi 窗口再试。”技术模式名只进详情。
- 多变更：“这几项修改还没有执行，已请 Pi 每次只提出一项。”仅在 Adapter 已实际把顺序重试原因返回 Pi 时使用后半句；不声称自动排队或已重新执行。
- 同一用户请求中再次出现同类批次阻止，不新增自动重试；提示返回对话调整目标。停止选择必须返回取消原因，让 Pi 不再为同一动作立即反复请求批准；若宿主不能保证停止后续提案，A-011/B-003 集成测试记录此限制，UI 不假称已停止整个任务。
- 不支持的能力只说产品限制；不能把所有被阻止动作都写成危险或恶意。不能建议把安装/启动任务改写为文件编辑，二者并不等价。
- 结果不符或无法确认时展示具体已知变化和一个下一步：返回 Pi 检查该文件，或在有依据时恢复。不得自动重跑可能已经产生修改的动作。

新增代理验收：具体目标识别、普通动作一屏、多危险完整显示、只读提示合并但检查独立、拒绝后不循环催促、备份失败无批准、弱证据不冒充内容正确、恢复冲突、原卡更新，并包含失败/不支持任务。它不产生真人理解结论。

B-003 的欢迎/帮助使用同一个 `agentglass-welcome` widget，不是第二审批界面；它只展示脱敏 cwd 名称、普通文本 read/write/edit 支持范围、当前最近结果、有效恢复入口和清理边界。固定示例准备仍使用已有 Stop 初始聚焦的单次审批卡，明确 `agentglass-example/活动说明.txt`、不覆盖冲突、部分失败保留且目录不可恢复。帮助还明确 Pi 0.85.1 没有由扩展可靠切换目录或打开文件的能力，用户应使用 Pi 已有项目/会话方式并在对话中请求查看。

## 8. Pi Web 卡片与连接行为（未来阶段，当前暂缓）

未来恢复阶段时，复用现有本地中文模板和同一逻辑动作卡，不单独设计网页系统。审批只能通过经安全验收的 Pi Web custom 桥接，结果用原有稳定 widget key 更新；欢迎、读取状态、最近结果和 /agentglass 帮助/示例/恢复/清理都须可用。当前已发布 `0.8.0` 仍只承诺 TUI；历史浏览器证据不构成当前 Web 兼容。

- 首次焦点为停止；默认 Enter、详情、关闭、Esc、超时与渲染异常不能批准。方向键/Tab 操作说明可保留，不依赖鼠标。
- 危险和未知在可批准状态下完整可达，窄视口允许滚动；折叠不得保留可盲目批准的入口。纯文本目标不作为 HTML 执行。
- 连接失效的待审批卡显示固定“这次确认已失效，请重新提出这一步”；服务端拒绝旧输入。该文案只说明批准失效，不推断整个任务或其他文件未改变。
- 已经或可能执行的动作连接中断时，说明结果尚不能确认；重连以当前安全事实更新结果，不自动再次执行，不显示旧批准已恢复。
- 一个请求只有一个拥有输入权的连接，其他标签页不能提交或接管；页面切换会话须使本页待审批失效，返回时新提案重新检查。
- 同一服务端会话仍有效时，重连可展示已有合格恢复入口；恢复/清理都用新审批。服务重启不重建授权或恢复入口。
- 欢迎/帮助明确只保护经 AgentGlass 审查的支持文件工具，不覆盖 Pi Web 上传、终端、Git 和配置操作。功能限制不暗示应关闭保护。

W-003 已在 Pi adapter 接通锁定 W-002 checkout 的版本化动态 bridge；确定性 Pi 调度和真实 Edge 7/7 回环会话均覆盖帮助、示例、read/write/edit、核验反馈、恢复和独立清理，普通 RPC、失效连接和能力漂移仍 fail closed，TUI 回归通过。真实浏览器的更宽布局、断线和安全故障矩阵属于 W-004；W-002 的真实 Chrome bridge 证据不替代本项真实 AgentGlass 文件闭环。
